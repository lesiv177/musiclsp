# Чекліст деплою MusicLSP (Етап 9)

Нічого з v7–v11 ще не задеплоєно. Виконуйте по порядку; кожен пункт — «зроблено / не зроблено».

## 1. Перед merge
- [ ] Створити feature-гілку, залити архів, відкрити PR.
- [ ] CI зелений: `python -m unittest discover -s tests -v` (тут включно з `test_api_hardening` — потрібен `aiohttp`), перевірка JS, asset validation, `tests/webapp_smoke.cjs`.
- [ ] Не зливати PR із червоним CI.
- [ ] Захищені файли не змінені (у корені проєкту): `sha256sum -c` на хешах нижче.

```
3e5b6212c676a26849d1748d19472f0345bfa83d90a485b2a010ee3142a2abab  core/connect.py
15317e3693ea683858da94cc06437096ed822e9a6b0313738364a37d2f29c21c  services/bot/main.py
```
Збережіть ці два рядки у файл `protected.sha256` і запустіть `sha256sum -c protected.sha256` — обидва мають бути `OK`.

## 3. Після деплою
- [ ] Railway задеплоїв саме потрібний commit (порівняти hash у Deployments із hash PR).
- [ ] Статус SUCCESS і 1/1 активна репліка — цього недостатньо, далі реальні запити:
- [ ] `MUSICLSP_BASE_URL=https://<ваш-домен> python scripts/prod_smoke.py` — усе `OK`.
- [ ] Те саме з `MUSICLSP_INIT_DATA` (initData з Telegram WebApp, DevTools → заголовок `X-Telegram-Init-Data`) — авторизовані GET-перевірки. Скрипт лише читає, нічого не змінює.
- [ ] У логах Railway немає `client_id=`, токенів, `Authorization` (редакція має їх закривати).
- [ ] Логи без помилок старту: немає `RuntimeError` про дублікати маршрутів.
