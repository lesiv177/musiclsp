## Звіт перевірки V12 і виправлення (v13, 9 листопада 2026)
Отримано від користувача: GitHub CI — 408 тестів, 32 помилки (16 failures + 16 errors); Railway — деплой SUCCESS, Online, 1/1; Audius — HTTP 400 і 429; Production Smoke — не виконано; iOS/Android — не завершено; у логах виявлено чутливі дані Connect.

| Проблема | Причина / що зроблено | Статус |
|---|---|---|
| Тести `test_api_hardening` (4 шт.) | Мій кеш профілів (v7) викликає `MC.cached` через `to_thread`, а тести цього не очікували. Тести оновлено (кеш імітується в `fake_to_thread`). Відтворено локально з заглушкою aiohttp. | Виправлено, ПЕРЕВІРЕНО ЛИШЕ ЛОКАЛЬНО |
| Решта помилок CI (≈28) | У моєму середовищі (Python 3.11 і 3.13, заглушка aiohttp) відтворюється лише 4 з 32; після виправлення 418/418 зелених. Причину решти без лога CI встановити не можна. | НЕ ВСТАНОВЛЕНО — потрібен лог CI (назви тестів і traceback) |
| Витік Connect у логах | WebSocket `/api/connect/ws` передає `initData` (підписаний, з hash) і `device_id` у query-рядку, а access-лог aiohttp пише повний URL. Мій редактор не ловив URL-кодований `initData`. Додано редакцію: query WS-маршруту, `initData=`, `device_id=`, `X-Telegram-Init-Data`, `hash=`/`hash%3D`. | Виправлено глобально в `core/log_safety.py` (Connect/плеєр НЕ змінювались). Перевірити в логах Railway вручну. Старі рядки в Railway лишаються — `initData` у них протермінований, але рекомендовано очистити/ротувати логи |
| Структурна причина витоку | Передача `initData` у query WebSocket — це код Connect (`webapp/index.html`, `services/bot/api.py`). Безпечніше передавати його першим повідомленням. Це зміна ЗАХИЩЕНОЇ ділянки. | ПОТРІБНЕ ВАШЕ ПОГОДЖЕННЯ, не змінювалось |
| Audius 429 | Після 429 тепер пауза для цього хоста (Retry-After, 5–120 с, типово 30 с); у паузі запити не надсилаються. | Виправлено, перевірено юніт-тестами; живу поведінку перевірити в Production |
| Audius 400 | Точна причина невідома (в логах не було, який endpoint). Захист: порожній запит і запит >100 символів більше не надсилаються, `limit` обмежено 1–100. У лог 400 тепер потрапляє endpoint і НАЗВИ параметрів (без значень). | Частково: після деплою за логами визначити реальний endpoint |

## ТОЧКА ЗУПИНКИ (оновлено 9 листопада 2026, v13)
**Зупинено на: Етап 9 — перевірка в Production. Код v13 готовий, але V12 не пройшла повну перевірку; «деплой SUCCESS» ≠ «все протестовано».**

Наступні кроки по порядку:
1. Надіслати лог GitHub CI (назви тестів, що падають, і traceback) — для решти ≈28 помилок.
2. Змерджити v13 → дочекатися зеленого CI → деплой → `scripts/prod_smoke.py`.
3. Подивитися логи Railway: немає `initData`/`device_id`; які Audius endpoint-и дають 400/429.
4. Погодити зміну передачі `initData` у Connect WebSocket (захищена ділянка) — або залишити як є з редакцією логів.
5. Ручна перевірка iOS/Android за `docs/DEPLOY_CHECKLIST.md`.
6. Рішення за вами: чи робити наявні плейлисти приватними (зараз `is_public=1`).
7. Етап 8 (Premium) та регіональні чарти — потрібні ключі/юридичні рішення/джерело даних.
Тести локально: 418 зелених (з заглушкою aiohttp, Python 3.11 і 3.13).

## Не змінювалося (захищені ділянки)
`core/connect.py`, `services/bot/main.py`, логіка відтворення, Player Widgets — без змін.

## Не перевірено
- Міграція `playlists.is_public` (ALTER у `init_db`) перевірена лише на SQLite; на PostgreSQL перевірити при першому деплої. Існуючі плейлисти лишаються доступними за посиланням (is_public=1 за замовчуванням) — вирішіть, чи робити їх приватними.
- `tests/webapp_smoke.cjs` у моєму середовищі (без мережі) падає на «Mobile dock overlap» — однаково на оригінальному архіві та на новому коді; у CI/на реальному пристрої перевірити. UI Radar візуально в браузері не перевірявся (лише `node --check` і контрактні тести).
- Запуск `tests/test_api_hardening.py` (потрібен `aiohttp`; у CI має працювати; тест чартів оновлено під нові жанри).
- Реальні HTTP-маршрути в Production, Telegram WebApp на iOS/Android, мобільна навігація.
- Жива доступність Audius/Jamendo та жанрів нових чартів (`classical`, `ambient`, `rnb`).
- Продуктивність каталогу на PostgreSQL (схема написана сумісно з SQLite/PG, перевірено лише SQLite).

## Не реалізовано
- Кеш — per-process, не спільний між репліками. Індекси каталогу додано в v12, але швидкість на PostgreSQL не вимірювалась.
- Перетягування (drag-and-drop) треків — замінено кнопками ↑/↓.
- Регіональні чарти, чарти за день, Global Top (немає валідних даних).
- Майбутні релізи (немає підтверджених джерел).
- Premium: платіжна інтеграція, історія платежів, керування підпискою.

- UI ручного підтвердження імпорту (v12) та UI редагування/перевпорядкування плейлистів лише перевірено `node --check` і контрактними тестами; у браузері/Telegram WebApp не перевірено.
- Редакція логів перевірена тестами; у Production-логах Railway перевірити вручну.

## Заблоковано (потрібні рішення/доступи)
- Платежі та ліцензійний аудит комерційного використання — потрібні ваші ключі й юридичні рішення.
- Persistent Queue між пристроями — лише через наявні механізми Connect, без змін захищених компонентів.

## Примітка про видалення даних
`/api/me/delete` видаляє бібліотеку, плейлисти, історію, підписки, чергу, пристрої й приховані рекомендації та
очищає `username`/`first_name`. Рядок акаунта (тариф, мова) лишається; повне видалення акаунта потребує окремого рішення.
